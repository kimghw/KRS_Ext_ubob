# 유밥 자동 학습 도우미 (Chrome 확장)

사이드 패널에서 **시작**을 누르면 끝까지 자동으로 진행합니다.

1. 저장해 둔 계정으로 **자동 로그인**
2. 내 강의실의 **학습중인 과정** 목록을 가져옴 (전체 신청 과정·수료 과정은 제외, 학습기간이 아직 시작되지 않은 신청 과정은 **예정**으로 표시만)
3. 과정마다 **아직 다 듣지 않은 강의만** 골라 배속(기본 2배속)으로 재생 (중간까지 본 강의는 안 본 구간부터)
4. 강의가 끝나면 다음 미완료 강의, 과정이 끝나면 **다음 과정**으로 이동
5. 모든 과정을 마치면 알림

재생은 화면에 보이지 않는 **백그라운드 플레이어**에서 진행됩니다. 강의 페이지를 열어 둘 필요가 없고, 다른 작업을 해도 됩니다.

## 설치

1. Chrome 주소창에 `chrome://extensions` 입력
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 폴더(`E:\dev\ubob`) 선택

> Chrome 116 이상이 필요합니다. 이전 버전(1.x)을 설치했었다면 확장 카드의 새로고침 버튼을 눌러 주세요.

## 업데이트 (머리의 GitHub 아이콘)

사이드 패널 머리 오른쪽의 GitHub 아이콘이 이 폴더(git 저장소)를 GitHub 과 맞춰 봅니다. 패널을 열 때 한 번, 그 뒤 10분마다 확인합니다.

| 모양 | 뜻 | 누르면 |
|---|---|---|
| 회색 | 최신 버전 | 다시 확인 |
| 강조색 + 숫자 | 새 커밋이 그 수만큼 있음 (풍선 말에 제목) | **받기** (`git pull --ff-only`) |
| 강조색 + ↻ | 받았고, 다시 불러와야 반영됨 | **확장 다시 불러오기** (패널이 닫힙니다 — 다시 여세요) |
| 숫자가 빨강 | 고치고 있는 파일과 겹치거나 올리지 않은 커밋이 있어 받을 수 없음 | 다시 확인 |
| 옅은 회색 + 머리 아래 "워크스페이스 브릿지 없음 · 직접 갱신하세요" | 브릿지가 없거나 이 확장이 등록되지 않음 | 다시 확인 |

git 은 같은 PC 의 KRS WORKSPACE 확장(`kr_ext_workspace`) 브릿지가 돌립니다(확장은 자기 폴더의 파일을 바꿀 수 없습니다). 그 확장 폴더에서 이 폴더를 한 번 등록하고, 이 확장을 새로고침합니다.

```powershell
node native\gitclient-setup.mjs add E:\dev\ubob
```

- **브릿지가 없으면 직접 갱신합니다**: 이 폴더에서 `git pull` 한 뒤 `chrome://extensions` 에서 확장 카드의 새로고침을 누릅니다.
- 받은 것이 설명·검사(`README.md`·`tests/`)뿐이면 다시 불러오지 않습니다. 받아 두고 다시 불러오지 않은 채 패널을 닫아도, 다시 열면 ↻ 가 그대로 보입니다.
- 폴더를 옮기면 확장 ID 가 바뀌므로 새 폴더로 다시 등록합니다. 받지 못한 까닭(GitHub 인증 등)은 머리 아래 줄에 나옵니다.
- 자동 학습 중에 다시 불러오면 진행 중이던 과정부터 이어집니다(아래 「문제 해결」).

## 사용법

1. 툴바의 확장 아이콘을 눌러 사이드 패널을 엽니다.
2. **계정** 칸에 사이트 주소(기본 `https://krs.ubob.com`), 아이디, 비밀번호를 넣고 **저장**합니다. 저장하면 바로 로그인을 시도하고 결과를 보여줍니다 (`로그인됨 · 이름` 또는 사이트의 오류 문구). 언제든 **로그인 확인**으로 다시 확인할 수 있습니다.
3. **목록 새로고침**으로 수강 과정 목록이 제대로 오는지 확인합니다 (재생 없이 목록만 가져옴).
4. **백그라운드 자동 학습 시작**을 누릅니다. 이후는 모두 자동입니다.
5. 진행 중에는 **플레이어 화면 보기**로 자동 학습이 보고 있는 화면을 창으로 볼 수 있습니다. 창 위쪽 상태줄에 지금 열고 있는 주소, 페이지 응답 여부, 재생 위치, 진도 저장 횟수가 나옵니다. 그 창을 닫으면 다시 보이지 않는 곳에서 이어서 재생합니다.
6. 무언가 이상하면 **진단**을 누르세요. 로그인 세션, 강의 페이지 응답(HTTP 상태·헤더·플레이어 유무·프레임 감지 코드), 플레이어 상태, 진도 저장 기록을 한 번에 모아 보여주고, **진단 결과 복사**로 복사할 수 있습니다.

사이드 패널에서 볼 수 있는 것:

- 지금 재생 중인 과정·강의, 진행 시간, 과정 진도율, **진도 저장 횟수와 마지막 저장 시각**, 이 강의의 진도율. 사이트가 진도를 저장할 때마다 갱신되므로, 이 숫자가 움직이면 실제로 학습이 기록되고 있는 것입니다. 목록의 과정 진도율도 함께 갱신됩니다.
- **학습중인 과정** 목록: 내 강의실의 "학습중인 과정" 분류만 보여줍니다. 과정별 진도와 상태(대기 / 학습 중 / 완료). 학습기간 시작일이 오늘보다 뒤인 신청 과정은 **예정**으로 함께 보여주며, 시작일 전에는 자동 학습 대상이 아닙니다. 체크를 풀면 그 과정은 건너뜁니다. **목록 새로고침**은 재생 없이 목록만 가져오며, 자동 학습 중에도 누를 수 있습니다.
- **내 강의실 열기**: 사이트의 나의 강의실(`/MyPage/MyRoom`)을 탭으로 엽니다. 저장된 계정으로 먼저 로그인해 두므로 로그인 화면 없이 바로 열리고, 이미 열려 있으면 그 탭으로 이동합니다. 목록의 **과정 이름**을 누르면 그 과정 페이지가 열립니다.
- **기록**: 로그인, 과정 시작, 강의 종료, 과정 완료 등

설정:

| 설정 | 기본값 | 설명 |
|---|---|---|
| 재생 배속 | 2.0x | 과정마다 사이트가 허용하는 최대 배속을 넘지 않음 |
| 백그라운드 재생 중 소리 끄기 | 켬 | 끄면 강의 소리가 스피커로 나옴 |
| 데스크톱 알림 | 켬 | 과정 완료, 전체 완료, 확인 필요, 로그인 실패 |
| 탭에서 직접 볼 때도 자동 진행 | 켬 | 강의 페이지를 직접 열었을 때 배속·다음 강의 자동 진행 (백그라운드 학습 중에는 중복 재생을 막기 위해 쉼) |

사이드 패널 맨 위 카드 (백그라운드 자동 학습에 적용):

| 설정 | 기본값 | 설명 |
|---|---|---|
| 근무 시간대에만 자동 학습 | 끔 · 09:00~18:00 · 평일만 | 켜면 설정한 시간대 밖에서는 자동 학습을 쉬고(플레이어를 비움), 시간이 되면 멈춘 과정부터 이어서 진행합니다. 시간 밖에서 **시작**을 누르면 로그인과 과정 목록만 준비해 두고 근무 시간에 재생을 시작합니다. 시작 시각이 끝 시각보다 뒤면 자정을 넘는 시간대로 봅니다. 카드 오른쪽에 `근무 중 · 18:00까지` 또는 `지금은 쉬는 시간 · 09:00 시작`이 표시됩니다. |
| 강의 사이 무작위 휴식 | 끔 · 최대 3분 | 강의 하나가 끝나면 다음 강의까지, 과정이 끝나면 다음 과정까지 1분과 입력한 최대 시간(분, 1~120) 사이에서 무작위로 쉽니다. 예: 5를 넣으면 1분~5분. 쉬는 동안은 아무것도 재생하지 않고, 사이드 패널에 남은 시간이 보입니다. 사용자가 **이 과정 건너뛰기**를 누른 경우에는 바로 다음 과정으로 갑니다. 재생 중에 켜고 끄거나 최대 시간을 바꾸면 바로 반영되며, 쉬는 중에 끄면 곧장 다음 강의로 넘어갑니다. 최소 1분은 `src/shared.js`의 `REST_MIN_SEC`. |

툴바 배지: `2x` 재생 중 · `...` 준비 중 · `zz` 휴식·근무 시간 대기 · `!` 확인 필요

### 플러스 탭 (러닝플러스)

사이드 패널 위쪽의 **유밥 / 플러스 / 알파** 탭 중 **플러스**는 러닝플러스(`https://krs.runningplus.net`)용입니다. 마지막에 본 탭은 다음에 사이드 패널을 열 때도 유지됩니다.

- **러닝플러스 계정**에 사이트 주소, 아이디, 비밀번호를 넣고 **저장**하면 바로 로그인을 시도하고 결과를 보여줍니다 (`로그인됨 · 이름` 또는 사이트의 오류 문구).
- **수강중 과정**: 나의 학습실의 "수강중 과정" 표(과정명·진도율·기간)를 사이드 패널에 보여줍니다. 플러스 탭을 열면 마지막 확인이 5분 넘게 지났을 때 자동으로 새로고침하고, **목록 새로고침**으로 언제든 다시 가져옵니다. 과정 이름을 누르면 나의 학습실이 탭으로 열립니다. 표가 안 잡히거나 이상하면 **구조 진단**으로 페이지 구조를 모아 **진단 결과 복사**로 전달해 주세요.
- **러닝플러스 열기**: 저장된 계정으로 먼저 로그인한 뒤 나의 학습실(`/Mystudy/MyStudyList.nm`)을 탭으로 엽니다. 로그인 화면 없이 바로 열립니다.
- 사이트가 계정을 거절하면(아이디·비밀번호 오류) 계정을 고치거나 **로그인 확인**을 누르기 전까지 같은 계정으로 자동 재시도하지 않습니다 (반복 실패로 계정이 잠기지 않게).

### 알파 탭 (로그인·수강신청·강의 재생)

툴바의 확장 아이콘을 누르면 페이지 옆 사이드 패널에 화면이 열리고, 다른 탭으로 옮겨도 계속 열려 있습니다. **알파** 탭에서 이미 신청한 과정은 **수강 중인 과정 백그라운드 학습**으로 재생하고, 신청부터 진행하려면 **미신청 과정 신청 후 학습**을 누릅니다.

1. **참여연구원 / 연구책임자** 중 본인 역할을 선택합니다. 연구비 집행·연구윤리·보안관리·성과관리·기타 **각 분야 1개씩 총 5개**가 선택됩니다. 연구윤리와 연구보안은 역할별로 서로 다른 과정입니다.
2. **알파 계정**에 아이디·비밀번호를 입력하고 **저장 및 로그인**을 누릅니다. 이미 사이트에 로그인되어 있으면 계정을 저장하지 않고 그 세션으로 시작할 수도 있습니다. 소속기관이 **한국선급**인지 확인하세요.
3. **수강 중인 과정 백그라운드 학습**은 선택한 알파 과정 1개 이상에서 이미 신청된 미완료 강의를 찾아 재생합니다. 새 수강신청을 보내지 않습니다. 미신청·승인 대기·학습 기간 종료 과정은 건너뛰고 **건너뛴 과정**에 이유를 표시하므로, 다른 과정의 신청 상태가 기존 강의 재생을 막지 않습니다. 수료한 과정은 다시 재생하지 않습니다. **미신청 과정 신청 후 학습**은 기존처럼 5개 분야를 모두 선택한 뒤 최신 신청 상태를 확인하고 미신청 과정만 순서대로 신청합니다.
4. 알파 강의실은 **화면에 보이지 않는 플레이어**에서 열리고 미완료 영상이 음소거·**1배속**으로 재생됩니다. 강의실 창이나 탭을 띄우지 않으며, 사이드 패널을 닫아도 Chrome이 실행 중이면 계속됩니다. 사이트에서 저장한 강의 완료 여부를 확인한 뒤 다음 강의로 이동합니다. 숨겨진 플레이어가 닫히거나(확장 새로고침 등) 응답·재생이 멈추면 사이트의 진도를 다시 조회해 자동으로 이어서 재생하고, 10분 안에 3번을 넘겨 반복되면 그 과정을 미뤄 두고 다음 과정의 강의로 넘어갑니다. 사이트는 차시 진도를 실제로 본 초(秒)의 수로 계산하고 다시 열면 마지막 위치에서 이어 재생하므로, 재생이 갑자기 끊겨 그때까지 본 구간이 저장되지 않으면 앞부분이 빈 채로 남아 끝까지 봐도 완료되지 않습니다. 그래서 이어 재생한 위치 앞에 안 본 구간이 있거나 끝까지 왔는데 안 본 구간이 남아 있으면, 그 첫 지점으로 되돌아가 거기서부터 봅니다(한 강의에서 두 번까지). 실행 중에 알파 로그인이 만료되면 멈추지 않고 저장된 계정으로 다시 로그인해 이어서 재생합니다(**로그인 확인**과 같은 로그인이며, 직전에 거절된 계정은 다시 보내지 않습니다). 계정을 저장하지 않았거나 로그인이 거절·추가 인증·중복 로그인 안내로 끝나면 그 이유를 보여 주며 멈추고, 로그인된 계정이 바뀌었거나 30분 안에 3번을 넘겨 다시 끊겨도 멈춥니다. 브라우저를 다시 켠 경우, 시험·설문, 직접 누른 중지는 자동으로 재개하지 않습니다. 강의를 마치면 수강 상태가 승인에서 미수료로 바뀌는데, 학습 기간 안의 미수료는 수강 중으로 보고 계속 재생합니다. 사이드 패널 상단의 **근무 시간대에만 자동 학습**과 **강의 사이 무작위 휴식**은 알파 재생에도 똑같이 적용됩니다(근무 시간 밖에서는 플레이어를 닫고 기다렸다가 이어서 재생, 끝까지 본 강의 뒤에만 휴식). 이 카드는 탭 줄이 움직이지 않도록 유밥·플러스·알파 모든 탭에서 보이며, 플러스 탭에는 재생 기능이 없어 영향이 없습니다. 유밥의 재생 배속은 알파에 적용되지 않습니다. 두 서비스가 숨겨진 문서를 공유하지만 재생 영역과 중지는 서로 독립적입니다.
5. **중지**하면 숨겨진 강의실을 비우고 후속 신청을 멈춥니다. 이미 전송된 신청 요청은 결과를 확인하고 마무리하며 취소하지 않습니다. 영상을 모두 본 과정에 설문만 남으면 실행을 멈추지 않고 다음 과정의 강의로 넘어갑니다. 설문과 수료증은 아래 분류 카드의 과정별 메뉴로 처리합니다. **설문 바로가기**는 그 과정의 설문 페이지를 바로 열고, **자동 설문**은 한 번 더 눌러 확인하면 모든 선택 문항을 "그렇다"(그 보기가 없으면 두 번째로 긍정적인 보기), 서술형을 "좋았다"로 제출하며, **수료증 받기**는 수료한 과정의 수료증을 저장합니다. 강사별·과목별 만족도처럼 자동으로 답할 수 없는 문항이 있으면 제출하지 않고 설문 바로가기를 안내합니다. 과정 이름 옆에 수강 상태가 표시됩니다(신청만 하고 아직 보지 않은 과정은 **수강신청**, 보기 시작했거나 지금 재생 중인 과정은 **수강중**, 영상을 다 보고 설문만 남으면 **설문 남음**, 수료하면 **수료완료**). 설문 바로가기는 영상을 모두 보고 설문만 남은 과정에서만, 수료증 받기는 수료한 과정에서만 눌립니다(알파 탭을 열 때와 실행이 과정을 넘길 때 과정별 수강 상태를 조회). 영상이 남은 과정에서 **자동 설문**을 누르면 **설문 예약됨**으로 바뀌며, 그 과정의 영상이 끝났을 때 실행이 설문을 제출하고 수료 확인·수료증 저장까지 이어 갑니다. 다시 누르면 예약이 취소됩니다. 이 메뉴는 백그라운드 재생 중에도 쓸 수 있습니다. 그 밖의 확인 단계는 **학습 화면 열기**에서 처리한 뒤 **다시 시도**할 수 있습니다. 재생 중 이 버튼을 누르면 숨김 재생을 먼저 멈춰 중복 재생을 방지합니다. 재개할 때 확장이 열었던 확인 탭이 같은 화면에 있으면 닫습니다.
6. 사이트에서 **수료 완료**가 확인되면 공식 수료증을 PDF로 자동 저장합니다. 이미 수료한 선택 과정도 자동 실행 시 확인합니다. 파일은 브라우저의 기본 다운로드 폴더 아래 **알파 수료증**에 저장되고, 사이드 패널의 **전체 수료증**에서 저장 완료·진행 중·실패 상태와 파일명을 확인할 수 있습니다. 발급 과정에서 알파의 공식 수료증 탭이 잠시 열렸다가 닫힙니다.

**강의 준비 중**에도 **중지**를 누를 수 있고, 강의실 주소가 확인되면 **학습 화면 열기**도 사용할 수 있습니다. 백그라운드 버튼은 준비·재생 상태를 표시하며 중복 실행을 막습니다. 준비가 1분 이상 끝나지 않으면 자동으로 다시 열고, 되풀이되면 그 과정을 미뤄 둔 뒤 다른 과정을 먼저 수강합니다. 플레이어 종료가 확인되지 않으면 중지 버튼이 유지되며, 중지를 다시 눌러 정리한 뒤 재시작할 수 있습니다.

**모두 수료증 받기**는 현재 알파 계정의 모든 연도·교육 유형의 수료 내역을 조회하고 수료증을 차례로 저장합니다. 역할이나 5개 과정 선택 없이 사용할 수 있으며, 첨부 양식 밖의 과거 수료 과정도 포함합니다. 기존에 저장한 수료증과 다운로드 중인 파일은 건너뛰고 실패한 항목은 다시 시도합니다. 조회 수·처리 수·과정별 결과가 표시되고, 한 과정의 발급 실패가 다음 과정 처리를 막지 않습니다. 학습·수강신청은 시작하지 않습니다.

사이드 패널을 닫아도 전체 받기는 계속되며, 다시 열면 진행 상태를 볼 수 있습니다. **전체 받기 중지**를 누르면 후속 발급을 멈추고 이미 시작한 다운로드는 유지합니다. Chrome 종료나 확장 새로고침으로 중단되면 **모두 수료증 받기**를 다시 눌러 이어서 확인하세요. 계정이 변경되거나 로그아웃되면 전체 받기를 중단합니다.

수료증은 계정과 수강 등록별로 다운로드 기록을 보관하여 중복 저장을 막습니다. 실제 파일 다운로드가 끝나야 **저장 완료**로 표시합니다. 발급 대기·통신 오류·사용자 취소가 있어도 다음 과정 학습은 이어집니다. **수료증 저장 확인·재시도**는 선택한 과정의 수료 여부를 다시 확인하고 아직 저장하지 못한 수료증을 받습니다. 설문·시험 등이 남아 있으면 발급하지 않으며, 이미 저장된 파일은 다시 내려받지 않습니다.

자동 재생 없이 신청만 하려면 역할 선택 옆의 **수강신청**을 누릅니다. 신청할 과정이 역할에 따라 달라지므로 버튼을 역할 선택과 같은 줄에 두었고, 미리 확인하지 않아도 과정마다 신청 가능 여부를 다시 확인한 뒤 미신청 과정만 신청합니다. 결과는 버튼 아래에 한 줄로, 과정별 결과는 맨 아래 **수강신청 목록**에 표시됩니다. 신청하지 않고 상태만 보려면 수강신청 목록의 **신청 가능 여부만 확인**을 씁니다. 역할 선택과 학습 시작은 별도 동작이며, 알파 탭을 열었다는 이유로 신청하거나 강의를 재생하지 않습니다. 기존 수강 과정만 학습한 실행은 **다시 시도**나 설문 완료 후 **계속**을 눌러도 새 수강신청을 보내지 않습니다.

첨부 파일에 직접 연결된 7개 과정/회차 중 역할에 맞는 5개를 사용합니다. 제목만 있는 대체 과정은 자동 선택하지 않습니다. 기간 종료·유료·별도 차시 선택·추가 입력 등이 필요한 과정은 자동 신청하지 않으며 **과정 상세 보기**에서 처리할 수 있습니다. 신청한 과정은 이 링크가 **강의실 열기**로 바뀌어 교육탐색의 과정 소개 대신 내 강의실의 그 과정을 엽니다(직접 진행할 설문·인터랙티브 차시가 남았으면 그 차시로). 같은 과정의 강의실 탭이 이미 열려 있으면 그 탭으로 이동합니다. 신청 결과를 확인하지 못하면 남은 신청을 멈추고, 다시 조회하기 전에는 자동 재전송하지 않습니다. 확장을 다시 로드해도 중단된 신청을 자동 재시도하지 않습니다.

신청과 이수는 별도입니다. **시험·추가 동의**는 자동 응답하지 않고 확인을 기다립니다. 설문은 사용자가 과정별 **자동 설문**을 눌렀을 때만 제출합니다. 시험은 자동으로 응시하지 않습니다. 시험이 있는 과정에는 **시험 바로가기**가 보이고, 영상을 모두 본 뒤 누르면 지금 보는 탭 바로 옆에 강의실을 열고 시험 표의 **현황** → **이어하기**를 대신 눌러 시험 창을 바로 띄웁니다(사이트는 주소만으로 시험 창을 열지 않고, 시험 차시 주소는 그 차시를 강의처럼 고르기만 합니다). 응시 중인 기록이 없으면 한 번 더 눌러 확인했을 때만 **응시**를 누릅니다(응시 횟수 1회 사용). 시험 바로가기 아래 칸에 답을 적고 **답 넣기**를 누르면(예: `1④ 2③ 5 O`, `1-4, 2-3`, 번호 없이 `4333…`) 응시 중인 시험 창에서 문항을 하나씩 열어 그 보기를 누릅니다. 사이트는 보기를 누를 때마다 답을 저장하므로, 저장이 끝난 것("답안 작성완료")을 확인한 뒤 다음 문항으로 넘어갑니다. 시험 창이 없으면 이어서 연 뒤 넣고, 새 응시를 시작하지는 않습니다. 읽기 애매한 답은 짐작하지 않고 되돌려 보내며, 넣지 못한 문항은 번호로 알려 줍니다. **제출은 직접** 합니다. 그 옆의 **시험 내용**은 누를 때마다 응시 화면의 문제와 보기를 사이트에서 새로 가져와 바로 복사합니다(다시 응시하면 문항이 바뀔 수 있습니다). 가져온 뒤에는 **복사하기**로 다시 복사할 수 있고, 새로 가져오지 못하면 지난 응시의 내용을 복사하지 않도록 지웁니다. 응시 중인 기록이 여럿이면 가장 최근에 시작한 것을 읽습니다. 답을 고르거나 제출하지 않으며, 채점 뒤에만 보이는 해설·정답은 가져오지 않습니다. 이미 응시 중인 기록이 있으면 그 문항을 그대로 읽어 응시 횟수를 쓰지 않고, 없으면 한 번 더 눌러 확인했을 때만 응시를 시작합니다(응시 횟수 1회 사용). 시험이 남은 과정이 있어도 실행은 멈추지 않고 다음 과정의 강의로 넘어가며, 설문은 시험을 마친 뒤에 열립니다. 지정된 연구윤리·성과관리 과정의 마지막 차시는 사이트가 "인터랙티브(저작도구)"로 분류하지만 실제로는 영상 하나를 저작도구 플레이어로 감싼 강의이므로 **일반 강의처럼 숨겨진 플레이어에서 재생합니다**(상호작용은 영상 끝의 링크·이미지뿐). 이 차시는 사이트가 실제로 본 구간의 합으로 진도를 계산하므로, 중간부터 이어 재생되더라도 아직 보지 않은 첫 지점으로 옮겨 거기서부터 봅니다. **강의가 재생되지 않거나 자동으로 더 진행할 수 없는 과정도 실행을 멈추지 않습니다**(영상을 찾지 못함, 강의실의 안내·응답 화면, 다시 열어도 되풀이되는 멈춤, 끝까지 봤는데 진도가 저장되지 않음, 수강 상태를 확인할 수 없음). 그 과정은 미뤄 두고 다른 과정의 영상을 먼저 수강하며, 실행 카드의 **건너뛴 과정**에 이유와 함께 표시합니다. 볼 수 있는 영상을 모두 본 뒤에 한 번만 **확인이 필요합니다**로 바뀌고, **학습 화면 열기**는 미뤄 둔 첫 과정의 강의실을 엽니다. 확인한 뒤 **다시 시도**하면 처음부터 다시 확인합니다. 조회 실패나 다시 로그인하지 못한 로그인 만료처럼 과정과 무관한 문제는 과정을 미루지 않고 그대로 멈춥니다. 사이트가 실제 수료로 표시한 경우에만 수료 완료로 안내합니다. 첨부 안내 기준 **2026년 수료**, **2026-12-18까지 증빙 제출**이 필요합니다.

자동 실행이 끝났는데 **설문이 남은 과정이 있으면 확장 아이콘 오른쪽 위에 주황색 알림 표시**가 나타납니다. 아이콘에 마우스를 올리면 설문이 남은 과정 수를 볼 수 있고, 과정별 자동 설문으로 모두 제출하면 사라집니다. 데스크톱 알림을 꺼 두어도 표시됩니다. **설문 완료 확인 후 계속**으로 확인하는 동안에도 표시를 유지하며, 사이트에서 설문 완료가 확인되어 다음 단계로 넘어가거나 중지하면 원래 아이콘으로 돌아옵니다.

로그인 추가 인증·비밀번호 변경·중복 로그인 안내가 뜨면 사이트에서 직접 처리해야 합니다. 거절되거나 결과가 불명확한 로그인은 같은 계정으로 자동 반복하지 않습니다. 계정을 수정하거나 **로그인 확인**으로 다시 시도할 수 있습니다. 브라우저를 재시작하면 자동 실행이 중지됩니다.

## 유밥에서 자동으로 처리하는 것 / 사람에게 넘기는 것

자동으로 처리:

- 로그인: 브라우저에 이미 로그인돼 있으면 그 세션을 그대로 쓰고, 세션이 없거나 만료됐을 때만 저장된 계정으로 로그인합니다. 강제로 로그인하는 것은 **로그인 확인** 버튼과 계정 저장 직후만입니다.
- 근무 시간 제한과 휴식: 30초마다 도는 감시 알람이 근무 시간을 확인해 시간 밖이면 쉬고 시간이 되면 이어서 진행합니다. 과정 사이 휴식은 끝나는 시각에 알람을 걸어 두므로 서비스 워커가 내려가도 정확히 깨어납니다. 확장을 새로고침해도 쉬던 상태를 이어 갑니다.
- "학습중인 과정입니다", "다음 콘텐츠 학습을 진행하시겠습니까?", "강의 끝났습니다" 같은 진행 확인창
- 이미 완료한 강의 건너뛰기, 중간까지 본 강의는 안 본 구간부터 재생
- 같은 강의를 3번 재생해도 진도가 안 차면 그 강의는 건너뛰고 계속
- 학습이 실제로 되고 있지 않으면 강의 페이지를 자동으로 다시 불러오기: 재생 중인데 영상 시간이 30초 동안 멈춤, 90초 동안 재생이 시작되지 않음, 재생 중인데 2분 30초 동안 진도 저장이 없음, 플레이어가 3분 넘게 응답 없음. 같은 과정에서 3번 넘게 다시 불러와도 안 되면 멈추고 이유를 알려줍니다.

멈추고 알림을 보내는 것 (사람이 판단해야 하는 것):

- 서약 동의, 퀴즈·시험·설문, 학습 신청이 필요한 과정, 로그인 실패, 그 밖의 사이트 경고

이때 사이드 패널에 **탭에서 열기**, **다시 시도**, **이 과정 건너뛰기** 버튼이 나타납니다. **플레이어 화면 보기**나 탭에서 직접 처리한 뒤 **다시 시도**를 누르면 이어서 진행합니다. 플레이어가 30초 안에 페이지를 못 열면 한 번 다시 시도하고, 그래도 안 되면 멈추고 알려줍니다.

그 밖에:

- 사이트가 정한 최대 배속(`maxSpeed`)을 넘지 않고, 배속이 막힌 과정(`noSpeed`)은 1.0배속으로 재생합니다.
- 진도 기록 API를 직접 호출하지 않습니다. 강의는 실제로 끝까지 재생되고, 진도는 사이트가 평소처럼 기록합니다.

## 동작 방식

로그인과 과정 목록은 확장 백그라운드에서 사이트 API를 직접 호출합니다 (Chrome 쿠키를 그대로 공유하므로 여기서 로그인하면 브라우저의 유밥 탭도 로그인 상태가 됩니다). 강의 재생만 플레이어에서 합니다.

일반 탭은 Chrome이 백그라운드에서 제약을 겁니다. 한 번도 화면에 보인 적 없는 탭에서는 영상 로딩을 미루고, 사용자 조작 없는 소리 재생도 막습니다. 그래서 탭 대신 확장 전용 **offscreen 문서** 안의 iframe에서 사이트를 그대로 실행합니다. 확장 페이지 안에서는 이 제약이 없습니다.

- 유밥의 프레임 제한은 기존 확장 플레이어 요청에 한해 처리합니다. 알파는 숨겨진 플레이어가 실행되는 동안 강의실·영상 프레임(`/catenoid.html`) 요청의 `X-Frame-Options`만 제거하고, 중지하면 이 규칙도 제거합니다. 알파의 CSP와 일반 탭 응답은 변경하지 않습니다. 알파 사이트의 서비스 워커가 영상 프레임을 저장본으로 응답하면 이 규칙이 적용되지 않아 프레임이 차단되므로, 숨겨진 강의실에서 열리지 않은 영상 프레임은 주소에 `?reload=1`을 붙여 네트워크로 한 번 다시 엽니다. 사이트의 서비스 워커나 저장본은 지우지 않습니다.
- 로그인 쿠키는 Chrome 쿠키 저장소를 공유합니다. 이미 Chrome에서 로그인되어 있으면 그 세션을 그대로 씁니다.
- 재생 중 로그인이 풀려 플레이어가 로그인 페이지로 가면, 백그라운드가 다시 로그인하고 과정 페이지로 돌려보냅니다.

- 과정 목록: `/api/myroom`(분류 목록) → 이름에 "학습중"이 든 분류만 `/api/myroom/$itemlist` (내 강의실과 같은 API). 예정 과정은 올해를 조회기간으로 "신청" 분류를 읽어 `startDate`가 오늘보다 뒤인 것만 추가
- 강의별 진도: 강의 페이지의 `orderContents`의 `studyProgress`, `studyTime`, `studyTimeList`
- 재생 위치 지정: 사이트의 `fnGoPosition` (미학습 구간 이동과 같은 기능)
- 러닝플러스 과정 목록: API 가 없어 나의 학습실(`/Mystudy/MyStudyList.nm`) 페이지의 과정 표(머리글 NO · 과정명 · 진도율 · 총 수강시간 · 기간 · 강의실)를 읽습니다. 열은 머리글 이름으로 찾습니다.

## 보안

- 비밀번호는 이 PC의 Chrome 프로필 안(`chrome.storage.local`)에 저장되며 동기화되지 않습니다. 암호화되지는 않으므로 공용 PC에서는 쓰지 마세요.
- 비밀번호는 설정한 `https://○○○.ubob.com` 사이트의 로그인 요청(`/api/auth/login`)에만 보냅니다. 러닝플러스 비밀번호는 설정한 `https://○○○.runningplus.net` 의 로그인 요청(`/Member/Proc/Login.nm`)에만 보냅니다.
- 알파 로그인·신청·학습 조회 요청은 `https://alpha-campus.kr`에만 보냅니다. 알파 계정을 저장하면 비밀번호도 이 PC의 `chrome.storage.local`에 저장되며 동기화되지 않습니다. 비밀번호는 정상 로그인 절차에만 사용하고 로그에 기록하지 않습니다. `cookies` 권한은 `XSRF-TOKEN` 요청 헤더와 사이트가 사용하는 브라우저 식별 쿠키를 처리하는 데 사용합니다. 인증 응답·토큰은 확장 저장소에 저장하지 않습니다.
- 수료증 발급에는 알파의 공식 보고서 사이트 `https://report.alpha-campus.kr`도 사용합니다. `scripting` 권한은 확장이 연 수료증 뷰어에서 원본 PDF를 내보내는 데, `downloads` 권한은 파일 저장과 완료 확인에 사용합니다. 확장 저장소에는 다운로드 상태만 보관하고 수료증 PDF 본문은 저장하지 않습니다.
- `nativeMessaging` 권한은 GitHub 아이콘이 워크스페이스 브릿지의 받기 전용 호스트(`com.krs.gitsync`)를 부르는 데만 씁니다. 보내는 것은 작업 이름(`gitStatus`·`gitPull`)뿐이고, 어느 폴더를 받을지는 브릿지가 이 PC 에 등록된 확장 ID 로 정합니다. 계정·비밀번호는 보내지 않습니다.

## 개발 확인

Node.js 18 이상에서 `node --test`로 역할별 선택, 신청 조건, 중복·세션 변경·통신 실패 처리를 검증합니다. 테스트는 모의 응답을 사용하고 실제 수강신청은 전송하지 않습니다.

## 문제 해결

- **로그인 실패**: 계정 칸에 사이트가 보낸 오류 문구가 그대로 나옵니다. **변경**에서 아이디·비밀번호·사이트 주소를 확인하세요. 비밀번호 변경 안내 등이 뜨는 계정이면 먼저 브라우저에서 직접 로그인해 처리해 주세요.
- **"로그인 응답은 성공했지만 로그인 상태가 유지되지 않습니다"**: Chrome 설정 → 개인정보 보호 및 보안 → 서드 파티 쿠키에서 `ubob.com`을 허용해 보세요.
- **"로그인이 짧은 시간에 반복해서 풀립니다"**: 이 사이트는 같은 계정으로 다른 곳(다른 PC·브라우저·모바일 앱)에서 로그인하면 기존 로그인이 풀립니다. 두 곳이 동시에 자동 학습을 돌리면 서로 상대의 로그인을 끊어 진도 저장이 실패하고 같은 구간을 반복합니다. 한 곳에서만 사용하세요.
- **어디서 멈췄는지 모를 때**: **진단**을 누르고 결과를 확인하세요. 사이드 패널 맨 아래 **기록**에도 단계별로 남습니다. 진행 중이면 **플레이어 화면 보기**로 실제 화면과 상태줄을 확인하세요.
- **플레이어 화면이 하얗게 비어 있음**: 상태줄이 "페이지가 열렸지만 아직 응답이 없습니다"이면 사이트가 프레임 안에서 내용을 숨기는 경우일 수 있습니다. 진단의 "프레임 감지 의심 코드" 줄을 확인하세요. "열어야 할 주소를 기다리는 중"이면 자동 학습이 과정 단계까지 가지 않은 것입니다.
- **"확인이 필요합니다"에서 멈춤**: **탭에서 열기**로 해당 과정을 열어 서약·설문 등을 처리한 뒤 **다시 시도**. 알파는 재생되지 않는 강의가 있는 과정을 미뤄 두고 다른 과정을 먼저 본 뒤에 이 상태가 됩니다(**건너뛴 과정** 참고).
- **확장을 새로고침(업데이트)했을 때**: 자동 학습이 실행 중이었다면 진행 중이던 과정부터 자동으로 이어서 진행합니다. 브라우저를 완전히 종료했다가 다시 켠 경우에는 멈추므로 사이드 패널에서 다시 시작하세요.
- **기록에 "플레이어가 다른 페이지(…)로 이동해 과정 페이지로 돌아갑니다"가 반복됨**: 2.0.0 초기 버전의 버그였습니다. 강의 페이지 안에 든 개인정보처리방침 iframe을 플레이어 본체로 잘못 인식한 것으로, 확장을 새로고침하면 해결됩니다.
- **사이트가 바뀌어 동작하지 않음**: 확인창 문구는 `src/page.js`의 `RULES`, 로그인과 과정 목록 API는 `src/background.js`의 `login()`, `fetchCourses()`에 있습니다.
